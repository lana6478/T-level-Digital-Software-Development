# Qualification Structure and Assessment

*Digital Software Development T Level → Overview → Qualification Structure*

This page covers the qualification summary table, entry requirements, and how the two mandatory components (Core and Occupational Specialism) are assessed.

## Qualification summary

| | |
|---|---|
| **Qualification title** | T Level Technical Qualification in Digital Software Development (Level 3) |
| **Qualification number (QN)** | 610/5801/4 |
| **First teaching** | September 2025 |
| **This qualification replaces** | 603/5832/4 T Level Technical Qualification in Digital Production, Design and Development |
| **Total Guided Learning Hours (GLH)** | 1260 hours (630 hours core) |
| **Total Qualification Time (TQT)** | 1740 hours (840 hours core) |
| **Occupational Specialism(s)** | Digital Software Development (630 GLH, 900 TQT) - there is only one |
| **Recommended age range** | 16-19 |

### Components and weighting

- Core Paper 1 = 30% of core (15% of total)
- Core Paper 2 = 30% of core (15% of total)
- Core Employer Set Project (ESP) = 40% of core (20% of total)
- Core Component = 50% of total
- Occupational Specialism = 50% of total

### Grading information

- Core and Employer Set Project (ESP) components are graded A*-E or Unclassified.
- The Occupational Specialism (OS) component is graded Pass, Merit, Distinction or Unclassified.
- The overall grading is on a scale of Pass, Merit, Distinction, Distinction* or Unclassified, awarded by the Institute for Apprenticeships and Technical Education (IfATE).

### Entry requirements

There are no formal prior learning requirements - it's the Provider's responsibility to ensure recruited students have a reasonable expectation of success. Students are most likely to succeed with Level 2 qualifications (e.g. 5 GCSEs at grade 4+ including English and maths, or a vocational Tech Award pass at Level 2), though relevant work experience or aptitude shown through diagnostic tests can also demonstrate readiness.

### Assessment

- The core and ESP components are externally set and marked by Pearson.
- The OS component is set by Pearson and externally marked by Pearson.

## Assessment structure

The qualification has two mandatory components.

### 1. Core component

Covers the underpinning knowledge, concepts and skills that support threshold competence in the digital industry.

| Assessment component | Method | Duration | Marks | Weighting | Availability |
|---|---|---|---|---|---|
| Core Paper 1 | Written examination | 2 hours 15 minutes | 90 | 30% | June/November |
| Core Paper 2 | Written examination | 2 hours 15 minutes | 90 | 30% | June/November |
| Employer Set Project | Externally set project | 14 hours 30 minutes | 100 | 40% | May/November |

### 2. Occupational Specialism component

There is **one** Occupational Specialism component in this Technical Qualification. It's assessed by a skills-related project that synoptically assesses the Performance Outcome skills and associated underpinning knowledge.

| Assessment component | Method | Duration | Marks | Weighting | Availability |
|---|---|---|---|---|---|
| Digital Software Development | Externally set project | 50 hours 30 minutes | 144 | 100% | Windowed, March to May |

## What does the qualification cover?

The content was designed from Outline Content created by IfATE and the Digital T Level panel, then validated by Pearson's own employer and Provider panel. Students learn about:

- Problem solving
- Introduction to programming
- Emerging issues
- Legislation and regulatory requirements
- Business context
- Data
- Digital environments
- Security

## Key terms

- **GLH / TQT** - Guided Learning Hours and Total Qualification Time, the two measures used to size a qualification.
- **Employer Set Project (ESP)** - the large, externally-set core assessment that synoptically tests skills built across the Core Component.
- **Windowed assessment** - an assessment (like the OS project here) that's completed within a set time window (March to May) rather than a fixed single date.

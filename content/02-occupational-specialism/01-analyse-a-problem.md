# Analyse a Problem

*Digital Software Development T Level → Occupational Specialism → Analyse a Problem*

This is Content Area 1 of the Digital Software Development occupational specialism: being able to analyse a problem to define requirements and acceptance criteria aligned to user needs. It walks through the whole software development lifecycle (SDLC), stage by stage, and covers the roles on a development team and the project methodologies used to plan and run software projects.

## 1.1 The software development lifecycle

The SDLC is a structured set of stages a digital project moves through, from first idea to ongoing maintenance:

- **Research and familiarisation** - understand the client's request/project brief, research the market and context (common problems/risks, current hardware/software use, emerging tech, existing solutions and how they meet user needs, industry regulations), and identify gaps in your own skills/knowledge so you can plan to fill them.
- **Planning and requirement analysis** - explore the brief and define the scope of a solution as a project proposal: identify business requirements (new software, added security, etc.), assess the proposed solution's value to the user and the client/business, apply computational thinking (decomposition, pattern recognition, abstraction) to break the problem into discrete parts, define functional and non-functional requirements, set key performance indicators (KPIs), identify performance constraints, write user acceptance criteria, schedule the project (tasks, subtasks, milestones), allocate resources, estimate costs, choose a programming language (weighing suitability, organisational policy, scalability, security, staff availability, cost, reliability), and identify risks and how to mitigate them.
- **Performing a user analysis** - use business analysis models to understand users and problems: user stories, activity diagrams, mind maps, product road maps, process diagrams, entity relationship diagrams.
- **Designing the product** - create interface designs, plan algorithms to solve key problems, create data requirements designs, and use generative AI tools to help produce sections of code, reviewing and refining the AI output to make sure it actually meets requirements.
- **Developing and testing the product** - build a prototype, then plan and run appropriate testing: module testing, system integration testing, automated testing, and user testing/feedback.
- **Deploying/implementing the product** - install and configure it, update it, document key changes/iterations, and keep proper version control.
- **Maintenance** - provide system and user support, fix bugs, arrange/carry out user training, and release updates that enhance the product.

Students also need to understand the value the digital product brings to the organisation, and the role the SDLC plays in delivering that value. *(Signposted competencies: E1-E5, M2, M6-M10, D1-D4.)*

## 1.2 Roles and responsibilities in the digital team

- **Product owner/client** - sets and communicates the product's requirements.
- **Scrum master** - keeps the team cohesive and makes sure they have the resources they need.
- **Technical lead** - provides technical guidance and support for the project team.
- **Project manager** - plans, organises and manages every phase of a project (budget, scope, schedule, risk, quality).
- **Software development team**: systems analyst (analyses the current system, writes requirements, designs the new solution), UX/UI designer (interviews users, researches the market, designs the interface), software developer/engineer (builds and maintains a usable, secure, stable solution from the designs), operations engineer (keeps the product stable), security engineer (keeps the product secure).
- **Software testers** - responsible for quality assurance across the software and the development process. *(E4, E5.)*

## 1.3 Project methodologies

Students need to understand the key features of each methodology and be able to select the right one for a given project:

- **Agile** - incremental delivery (sprint, epic, story, spike), high-quality products with initially limited functionality, each increment adds functionality, requirements can keep changing, can lack formal documentation, users see working products every iteration, cost-effective route to an initial market product, and even a cancelled project usually leaves some usable code.
- **Scaled Agile** - Agile's incremental model expanded to include product increments, with cohesive reporting across larger teams, and a final iteration focused on stability.
- **Waterfall** - rigid, systematic steps; progress measured by artefacts completed; high upfront cost with a slower return on investment; a project cancelled early may leave nothing usable; limited user/client interaction; heavy emphasis on documentation.
- **Rapid Application Development (RAD)** - fast prototyping that's systematically improved; features come before quality; users may only see partial/mock-up products early on; relies heavily on reusing existing code; best for small-to-medium projects.
- **Lean** - focused on cutting "waste" (unnecessary features, repeated tasks, over-complex solutions, poor communication, unnecessary changes); decisions deferred to the last responsible moment; short, fast iteration cycles; prioritises iterations that are fit for use over delivering every feature; suited to small teams with limited resources.
- **User Centred Design (UCD)** - considers who the user is, what they want to achieve, how/when/why they interact with the product, and their overall experience; characterised as empathetic, iterative and interdisciplinary; follows an iterative cycle of understanding the context, specifying requirements, designing the solution, and assessing it against requirements. *(E5, D1, D3, D6.)*

## 1.4 Functional and non-functional requirements

- **Secure by design** - security is built into a decision from the start, shaping both functional and non-functional requirements.
- **Functional requirements** define: the inputs needed, the data needed, the data processing that must happen, the system's logic, and the platforms the software will run on.
- **Non-functional requirements** define: security considerations, required accessibility features, scalability, KPIs/metrics for responsiveness/load handling/reliability, and user acceptance criteria.
- **Spike testing** - an early testing technique used to establish requirements and work out the scope of a problem and the solution needed. *(E1, E5, M2, M6-M8, D2, D3, D6.)*

## 1.5 Emerging technologies

Students investigate how emerging technologies are affecting software development and industry more broadly, including: operational technology (OT); artificial intelligence (AI) and virtual intelligence (VI) and their subsets (conversational/generative AI, machine learning, object recognition, computer vision); the Internet of Things (IoT); biometrics; robotics and automation; cloud services and platforms; data lakes and data warehousing; drones; 3D printing; and developments in communications networks (e.g. 5G, wider broadband availability). *(E1-E4.)*

## 1.6 Identifying and addressing training needs

To make sure they can actually deliver a solution, developers need to be able to: identify what further knowledge and skills they need, and judge whether they're currently able to complete the required work. They can then address gaps by: coaching from a professional or peer, learning on the job, self-study, using professional online forums, or signing up to online workshops. *(E5, E6, D1, D3, D6.)*

## Key terms

- **SDLC (Software Development Lifecycle)** - the structured stages a digital project moves through, from research to maintenance.
- **KPI** - key performance indicator, a measurable target used to judge a solution's success.
- **Functional requirement** - what a system must do (inputs, data, processing, logic, platform).
- **Non-functional requirement** - how well a system must do it (security, accessibility, scalability, performance).
- **Spike testing** - early testing used to establish requirements and scope before full development.
- **Agile / Waterfall / RAD / Lean** - project methodologies, each with different trade-offs between speed, documentation, flexibility and team size.

# Occupational Specialism: Scheme of Assessment

*Digital Software Development T Level → Occupational Specialism → Scheme of Assessment*

Unlike some T Levels, Digital Software Development has a **single synoptic assessment** for its one occupational specialism: one extended project, rather than a choice of several. The synoptic element matters because it's how students demonstrate threshold competence and provide evidence against every skill listed in the Performance Outcomes at once, rather than in isolated pieces.

## How the project is structured

The project is externally assessed, runs for **50 hours 30 minutes** in total, and is worth **144 marks**. It's made up of several activities grouped into four substantive tasks:

- **Task 1**: Analysing a problem and designing a solution.
- **Task 2**: Developing the solution.
- **Task 3a**: Gathering feedback.
- **Task 3b**: Evaluating feedback.

Each task runs during a window set by Pearson, during which providers schedule supervised assessment sessions; some tasks also allow unsupervised activity where that's genuinely needed for the skill being assessed. Students respond to a given scenario to complete the whole project, assessed on how they apply the skills listed under the Performance Outcomes below - they are not assessed against separate "knowledge" outcomes, but are expected to draw on and apply that knowledge naturally while completing the tasks.

Students work under a mix of supervised and controlled conditions, and internet access is permitted for every task **except** Task 3b. The finished project is a portfolio of evidence submitted electronically, and it's externally marked by Pearson.

**Use of AI.** For Task 1 Activity C, students are expected to use a generative AI model (Pearson doesn't specify which, though a natural-language model like ChatGPT or Google Gemini is suggested) to create short code snippets addressing a specific piece of functionality - not to generate a single overarching solution to the whole brief. The chosen AI tool should let students show the specific prompts they used and review how well the output met the functionality it was meant to address.

## Performance Outcomes and weighting

| Performance Outcome | Raw marks | % of total marks |
|---|---|---|
| **PO1** Analyse a problem to define requirements and acceptance criteria, aligned to user needs | 24 | 16.7% |
| **PO2** Design, implement and test software | 57 | 39.6% |
| **PO3** Change, maintain and support software | 18 | 12.5% |
| **PO4** Create solutions in a social and collaborative environment | 9 | 6.3% |
| **PO5** Discover, evaluate and apply reliable sources of knowledge | 18 | 12.5% |
| **PO6** Apply ethical principles and manage risks in line with legal and regulatory requirements when developing software | 18 | 12.5% |

PO2 (design, implement and test) carries by far the most weight, at nearly 40% of the total - reflecting that it's the core technical work of actually building the software solution.

## Grading

The project is graded on the qualification's Occupational Specialism scale of **Pass, Merit, Distinction or Unclassified**, based on the total marks achieved against the 144 available. See [Grading and Results](../00-overview/04-grading-and-results.md) for how this combines with the Core Component grade into an overall T Level grade.

## Delivery resources

Providers need staff with relevant qualifications and/or experience in the digital sector, and a curriculum team whose combined knowledge spans the full breadth of the qualification content.

**General resources**: software supporting Python 3.10+ and the other selected coding languages; word processing and spreadsheet software (e.g. MS Office); data back-up solutions (external hard drives, network storage, cloud file stores); data encryption software (e.g. MS BitLocker); internet access; a printer.

**Specific resources**: an IDE and debugger appropriate to the chosen languages; automated testing tools covering UI, performance, load/stress and compatibility testing; access to communication/collaboration/data-collection tools including online code repositories (e.g. GitHub), forums (e.g. Stack Overflow), and questionnaire/survey tools (e.g. Google Forms, SurveyMonkey); access to AI code-generation resources; access to online third-party digital content (video/graphics); screencasting and video editing software; microphones and headphones.

## Key terms

- **Synoptic assessment** - a single assessment that draws together and evidences skills from across the whole specialism, rather than testing each skill in isolation.
- **Performance Outcome (PO)** - one of the six defined skill areas the project is marked against.
- **Portfolio of evidence** - the electronically-submitted collection of work produced across the project's tasks.

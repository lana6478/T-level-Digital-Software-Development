# Design

*Digital Software Development T Level → Occupational Specialism → Design*

This is Content Area 4 of the Digital Software Development occupational specialism: understanding common design approaches, choosing the right platforms for source code and content management, and designing a software solution end to end - from UX/UI principles through to database and network design.

## 4.1 Common design approaches

Students use critical thinking to pick the right design approach for a project, and apply it within the wider project methodology:

- **Function-oriented (top-down) design** - focuses on how data flows through the system; the system is broken into sub-systems (functions); data flow diagrams show how each function handles or changes data; the problem is logically divided based on what each function should do ("divide and conquer").
- **Object-oriented programming (OOP) design** - makes code reusable through standard OOP structures (methods, classes, objects/instances); characterised by encapsulation, data abstraction, polymorphism and inheritance; uses common OOP design patterns (creational, structural, behavioural).
- **Data model design** - visualises what data is needed and how it's organised, using common data models (conceptual, logical, physical, hierarchical, relational) and tools such as the Entity Relationship Model (E-R Model) and Unified Modelling Language (UML).
- **Test-driven development (TDD)** - every new feature starts with a test that defines what the feature should do; the cycle is: add a test, run all tests until the new one fails, write the code, run tests and refactor, repeat.
- **Behaviour-driven development (BDD)** - development is driven by the required behaviour of a software unit, specified before coding starts; desired behaviours must have business value and map to specified requirements; behaviour specifications typically follow a title/narrative/acceptance-criteria structure.
- **Functional design** - the program is structured as a set of modules, each performing one defined process/function; characterised by recursion, closures, first-class functions, higher-order functions, anonymous functions and currying; built from arguments, statements, blocks, procedures and functions/sub-routines.

*(Signposted competencies: E1-E5, M1-M8, M10, D1, D2, D4, D6.)*

## 4.2 Platforms for source code and content management

Students need to understand the features of development platforms at each stage: coding, repositories, branching, building, testing, deployment. This includes understanding:

- The differences between **proprietary** and **open-source** platforms, and how that choice affects design.
- Development workflow management approaches (**GitFlow**, **GitHubFlow**).
- How to weigh up different platforms and make an informed choice based on: target audience, budget, technical features, staff and training, ease/speed of development, platform updates, security, reliability, performance, and compatibility.

*(E1, E3, E5, M10, D1-D6.)*

## 4.3 Designing a software solution

- **UX design principles**: consistency (intuitive, aesthetically pleasing, on-brand), information hierarchy (easier navigation), visual hierarchy (important content stands out), confirmation (users know what actions they've taken and their impact), user control (efficient navigation, workflow and error correction), and accessibility (works for a wide range of users).
- **UI design principles**: wireframes, style guides, clickable prototypes.
- **Content management system (CMS) features**: SEO, page/screen management, social media integration, analytics tools, workflow management, publishing controls, security features, versioning and rollback, content repositories, open APIs, multilingual support, and general support.
- **Program design conventions**: pre-defined code, flowcharts using standard BCS symbols, pseudocode using standard notation, control structures (sequence, selection/branching, iteration), data types, data validation, and data structures.
- **Selecting assets** (graphics, audio, video, code): considering file types, file size, compression, streaming/encoding audio and video, metadata use, required quality, available bandwidth/storage, and the target platform.
- Working **legally and ethically when using AI** to generate content or assets for a software solution.
- **Target platforms** and how they shape design/development: operating systems, file systems, server/infrastructure (physical and virtual), the programming language stack, and mobile vs. web.
- **Using databases** to support a solution: user management, e-commerce tasks (stock, order processing, page personalisation), diagnostics, and performance analysis. Database designs are created using a data dictionary/library, an entity relationship diagram (ERD), and normalisation to third normal form.
- **Network integration points**: which data is processed locally (e.g. user input in a game) vs. remotely (e.g. actions of all players in a multiplayer game), how data moves between local and remote sources (e.g. remote system calls), how local and remote systems connect, where the system boundaries sit, and which external systems to integrate with (e.g. a sports-data feed).

*(E1-E5, M1-M8, M10, D1-D4, D6.)*

## Key terms

- **OOP (Object-Oriented Programming)** - a design approach built on classes, objects, encapsulation, abstraction, polymorphism and inheritance.
- **TDD / BDD** - test-driven / behaviour-driven development, where tests or required behaviours are defined before the code that satisfies them.
- **ERD (Entity Relationship Diagram)** - a diagram showing how data entities relate to each other, used in data model and database design.
- **Third normal form** - a level of database normalisation that reduces data redundancy and dependency issues.
- **GitFlow / GitHubFlow** - structured branching workflows for managing code changes in a repository.

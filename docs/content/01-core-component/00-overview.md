# Core Component Overview

*Digital Software Development T Level → Core Component*

The **Core Component** is the shared foundation every student studies before specialising. It covers the underpinning knowledge and skills that support **threshold competence** across the digital sector - problem solving, programming fundamentals, business context, data, digital environments and security - and is assessed through two written exam papers plus an Employer Set Project.

## Purpose

The Core Component builds the knowledge base that underpins software development work generally: how to break down and solve problems, how to write and reason about code, the business and legal context software is built within, how data is structured and used, the hardware/network/cloud environments code runs in, and the security risks that come with all of it. The Occupational Specialism then goes deep on the practical craft of designing, building, testing and maintaining software itself.

## The three assessments

| Part | What it covers | Weighting (of the core) |
|---|---|---|
| [Core Paper 1](01-core-paper-1.md) | Problem solving · Introduction to programming · Emerging issues · Legislation and regulatory requirements | 30% (90 marks, 2h 15m written exam) |
| [Core Paper 2](02-core-paper-2.md) | Business context · Data · Digital environments · Security | 30% (90 marks, 2h 15m written exam) |
| [Employer Set Project](03-employer-set-project.md) | A substantial, externally set and marked project (14h 30m) drawing synoptically on the whole core | 40% (100 marks) |

For exact assessment objective breakdowns and exam structure, see [Core scheme of assessment](04-core-scheme-of-assessment.md).

## Key terms

- **Threshold competence** - having the core knowledge and skills needed to be ready to build full occupational competence on the job.
- **Synoptic assessment** - assessment (here, the Employer Set Project) that draws together knowledge and skills from across the whole core component rather than testing isolated topics.
